SUB Tracing Mechanism - Detailed Specification and Plan
=======================================================

Date: 2026-02-12 (updated 2026-02-17: added TRON/TROFF)
Branch: sub-tracing (from master)

Overview
--------
Add a compile-time flag (-t) that instruments every SUB with entry/exit trace
calls, combined with TRON/TROFF statements for runtime control. At runtime,
a trace library writes to T:ace_trace.log showing:
  - SUB entry with name and parameter values
  - SUB exit with name and return value
  - Indentation for nested/recursive calls

The -t flag instruments all SUBs with trace hooks. By default, tracing is
active (all SUB calls are logged). The user can use TRON (Trace ON) and
TROFF (Trace OFF) statements to selectively enable/disable trace output
at runtime, limiting it to specific code regions.

Output format example (full tracing with -t):
  -> Add(3, 5)
  <- Add = 8
  -> ProcessList($41A0, 42)
    -> Helper(42)
    <- Helper = 84
  <- ProcessList = 1

Output format example (selective tracing with TRON/TROFF):
  Source:
    result = Calculate(10, 20)    ' not traced
    TRON
    result = Calculate(10, 20)    ' traced
    TROFF
    result = Calculate(10, 20)    ' not traced

  T:ace_trace.log:
    -> Calculate(10, 20)
    <- Calculate = 30

Scope
-----
- Only user-defined SUBs are traced (not DEF FN, not library calls)
- CALLBACK SUBs are NOT traced (called from external C/asm, different param setup)
- INVOKABLE SUBs are traced (with d0 return)
- Module SUBs (compiled with -m -t) are traced (with d0 return)
- Does NOT trace: system library calls, implicit type conversions,
  expression evaluation, or DEF FN
- TRON/TROFF only have effect when compiled with -t; without -t they
  are accepted but generate no code (no-ops)

Components
----------
1. Compiler flag (-t)
2. TRON/TROFF statements (lexer + statement handler)
3. Compiler instrumentation (parse.c block())
4. Runtime trace library (new: src/lib/asm/trace.s)
5. Build system updates (Makefile-lib, bas script)
6. acedef.h changes (SYM struct)

    Add to rword[] array (in alphabetical position):
    "TRON"  -> tronsym
    "TROFF" -> troffsym

2c. Statement handlers in statement.c:
    In the statement() dispatcher, add cases:

    case tronsym:
        if (trace_opt)
        {
            gen("move.w","#1","_trace_enabled");
            enter_XREF("_trace_enabled");
        }
        insymbol();   /* consume TRON token */
        break;

    case troffsym:
        if (trace_opt)
        {
            gen("clr.w","_trace_enabled","  ");
            enter_XREF("_trace_enabled");
        }
        insymbol();   /* consume TROFF token */

  A) Program startup  -> open trace file
  B) SUB entry        -> log name + parameters
  C) SUB exit         -> log name + return value

        char trace_label[80], trace_data[200];
        char addrbuf[40];
        int pi;

        /* Create string constant with SUB name (without _SUB_ prefix) */

        sprintf(trace_label, "_tn%d", tracename_count);
        tracename_count++;

        /* Save registers we'll clobber */
        gen("movem.l","d0-d2/a0-a1","-(sp)");

        /* Call _trace_enter(name_ptr) - name in a0 */
        gen("lea", trace_label, "a0");
        gen("jsr", "_trace_enter", "  ");
        enter_XREF("_trace_enter");

        /* Emit each parameter value */
        for (pi = 0; pi < sub_ptr->no_of_params; pi++)
        {
            if (pi > 0)
            {
                gen("jsr", "_trace_param_sep", "  ");
                enter_XREF("_trace_param_sep");
            }

            /* Compute parameter's frame address */
            /* Parameters are local variables - they have been entered
               into the symbol table by sub_params(). We need to find
               them. However, we don't have easy access to them by index.

               Alternative: parameters are at known offsets.
               With sub_params, each param is entered as a variable via
               enter(). The addresses are sequential from addr[lev].
               But we can recompute: first param is at offset -8 (for
               longs) or sequential negative offsets.

               Simpler approach: iterate the frame by type.
               Parameter offsets in the callee frame:
                 First param:  smallest negative offset after -0
                 Each short takes 2 bytes, each long takes 4 bytes
                 Starting at offset = first allocation after link.

               Actually, sub_params() creates variables via enter()
               which allocates them in addr[lev]. So param 1 is at
               the first allocation, param 2 at the next, etc.

               We CAN compute this: walk from -2 or -4 up.
               But easier: we store param addresses during emission.
            */

            /* See implementation note below */
        }

        gen("jsr", "_trace_end_params", "  ");
        enter_XREF("_trace_end_params");

        /* Restore saved registers */
        gen("movem.l","(sp)+","d0-d2/a0-a1");

IMPLEMENTATION NOTE - Parameter Address Discovery:

The challenge is that sub_params() has already run when we emit trace
code, so the parameter variables exist in the symbol table as local
variables at level ONE. We need their frame addresses.

Approach: Add a small array to store parameter addresses during
sub_params(). In sub.c sub_params(), after each enter() call (line 326),
save the address:

    sub_ptr->p_addr[param_count] = curr_item->address;

This requires adding p_addr[MAXPARAMS] to the SYM struct in acedef.h.
(Small change, MAXPARAMS is already 12.)

Then in the trace emission, for each parameter:

    gen_frame_addr(sub_ptr->p_addr[pi], addrbuf);

    switch (sub_ptr->p_type[pi])
    {
        case shorttype:
            gen("move.w", addrbuf, "d0");
            gen("jsr", "_trace_param_short", "  ");
            enter_XREF("_trace_param_short");
            break;
        case longtype:
        case longtype:  /* ADDRESS is stored as longtype */
            gen("move.l", addrbuf, "d0");
            gen("jsr", "_trace_param_long", "  ");
            enter_XREF("_trace_param_long");
            break;
        case singletype:
            gen("move.l", addrbuf, "d0");
            gen("jsr", "_trace_param_single", "  ");
            enter_XREF("_trace_param_single");
            break;
        case stringtype:
            gen("move.l", addrbuf, "a0");
            gen("jsr", "_trace_param_str", "  ");
            enter_XREF("_trace_param_str");
            break;
    }

For CALLBACK SUBs: skip tracing (parameters come from registers, not
frame - and CALLBACKs are called from C/asm, not from BASIC).

For INVOKABLE SUBs: trace normally (called like regular SUBs).

============================================================
COMPONENT 4: Runtime Trace Library
============================================================

New file: src/lib/asm/trace.s

The trace library uses AmigaDOS file I/O directly. All functions are
small, leaf-style routines that preserve caller's registers.

Calling convention:
  - _trace_enter:        a0 = pointer to SUB name string (null-terminated)
  - _trace_param_long:   d0 = LONGINT value
  - _trace_param_short:  d0.w = SHORTINT value
  - _trace_param_single: d0 = FFP float (raw 32 bits)
  - _trace_param_str:    a0 = pointer to string data
  - _trace_param_sep:    (no params)
  - _trace_end_params:   (no params)
  - _trace_exit_void:    a0 = pointer to SUB name string
  - _trace_exit_long:    a0 = name, d0 = LONGINT return value
  - _trace_exit_short:   a0 = name, d0.w = SHORTINT return value
  - _trace_exit_single:  a0 = name, d0 = FFP return value
  - _trace_exit_str:     a0 = name, then string addr also in a0?
                          Actually: a0 = name, a1 = string return value
  - _trace_open:         (no params) - opens T:ace_trace.log
  - _trace_close:        (no params) - closes the file

REVISED calling convention for exit functions:
  - _trace_exit_*:   a0 = name string, d0 = return value (or a1 for str)
  This means we need to load both the name pointer AND the return value
  before calling. The compiler instrumentation handles this.

Internal state (BSS):
  _trace_fh:      ds.l 1    ; file handle from Open()
  _trace_enabled: ds.w 1    ; 0 = tracing off, 1 = tracing on
  _trace_depth:   ds.w 1    ; nesting depth (for indentation)
  _trace_buf:     ds.b 256  ; formatting buffer

Internal helpers:
  _trace_indent   - write (depth * 2) spaces
  _trace_write    - write string at a0 to trace file
  _trace_ltoa     - convert d0.l to decimal string in buffer
  _trace_stoa     - convert d0.w to decimal string in buffer

Implementation (~250-300 lines of 68000 asm):

;----- _trace_open -----
; Open T:ace_trace.log for writing, enable tracing by default
_trace_open:
    movem.l d0-d1/a0-a1/a6,-(sp)
    move.l  _DOSBase,a6
    lea     _trace_filename,a0
    move.l  a0,d1
    move.l  #1006,d2           ; MODE_NEWFILE
    jsr     _LVOOpen(a6)
    move.l  d0,_trace_fh
    move.w  #1,_trace_enabled  ; tracing ON by default
    clr.w   _trace_depth
    movem.l (sp)+,d0-d1/a0-a1/a6
    rts

;----- _trace_close -----
_trace_close:
    movem.l d0-d1/a6,-(sp)
    move.l  _trace_fh,d1
    beq.s   .done
    move.l  _DOSBase,a6
    jsr     _LVOClose(a6)
    clr.l   _trace_fh
.done:
    movem.l (sp)+,d0-d1/a6
    rts

;----- _trace_enter -----
; a0 = name string
_trace_enter:
    movem.l d0-d3/a0-a3/a6,-(sp)
    tst.w   _trace_enabled
    beq.s   .done
    move.l  _trace_fh,d1
    beq.s   .done
    move.l  a0,a2              ; save name
    bsr     _trace_indent
    ; write "-> "
    lea     _trace_arrow_in,a0
    bsr     _trace_write
    ; write name
    move.l  a2,a0
    bsr     _trace_write
    ; write "("
    lea     _trace_lparen,a0
    bsr     _trace_write
    ; increment depth
    addq.w  #1,_trace_depth
.done:
    movem.l (sp)+,d0-d3/a0-a3/a6
    rts

;----- _trace_param_long -----
; d0.l = value
_trace_param_long:
    movem.l d0-d3/a0-a3/a6,-(sp)
    tst.w   _trace_enabled
    beq.s   .done
    move.l  _trace_fh,d1
    beq.s   .done
    ; d0 already has the value (saved on stack, need to reload)
    move.l  28(sp),d0          ; d0 from saved registers
    lea     _trace_buf,a0
    bsr     _trace_ltoa        ; convert d0 to string at a0
    bsr     _trace_write       ; write buffer
.done:
    movem.l (sp)+,d0-d3/a0-a3/a6
    rts

;----- _trace_param_short -----
; d0.w = value
_trace_param_short:
    movem.l d0-d3/a0-a3/a6,-(sp)
    tst.w   _trace_enabled
    beq.s   .done
    move.l  _trace_fh,d1
    beq.s   .done
    move.l  28(sp),d0          ; d0 from saved regs
    ext.l   d0                 ; sign-extend to long
    lea     _trace_buf,a0
    bsr     _trace_ltoa
    bsr     _trace_write
.done:
    movem.l (sp)+,d0-d3/a0-a3/a6
    rts

;----- _trace_param_single -----
; d0 = FFP float (raw 32 bits)
; Display as hex since FFP->decimal is complex.
; Format: $XXXXXXXX (f)
_trace_param_single:
    movem.l d0-d3/a0-a3/a6,-(sp)
    tst.w   _trace_enabled
    beq.s   .done
    move.l  _trace_fh,d1
    beq.s   .done
    move.l  28(sp),d0          ; d0 from saved regs
    lea     _trace_buf,a0
    move.b  #'$',(a0)+

    move.b  #0,(a0)
    lea     _trace_buf,a0
    bsr     _trace_write
.done:
    movem.l (sp)+,d0-d3/a0-a3/a6

    move.l  36(sp),a0          ; name

    lea     _trace_equals,a0
    bsr     _trace_write
    lea     _trace_quote,a0
    bsr     _trace_write
    move.l  32(sp),a0          ; a1 = string value (from saved regs)
    bsr     _trace_write_trunc
    lea     _trace_quote,a0
    bsr     _trace_write
    lea     _trace_nl,a0
    bsr     _trace_write
.done:
    movem.l (sp)+,d0-d3/a0-a3/a6
    rts

;----- _trace_exit_void -----
; a0 = name (no return value)
_trace_exit_void:
    movem.l d0-d3/a0-a3/a6,-(sp)
    tst.w   _trace_enabled
    beq.s   .done
    move.l  _trace_fh,d1
    beq.s   .done
    subq.w  #1,_trace_depth
    bsr     _trace_indent
    lea     _trace_arrow_out,a0
    bsr     _trace_write
    move.l  36(sp),a0
    bsr     _trace_write
    lea     _trace_nl,a0
    bsr     _trace_write
.done:
    movem.l (sp)+,d0-d3/a0-a3/a6
    rts

;===== Internal helpers =====

;----- _trace_indent -----
; Write (depth * 2) spaces to trace file
_trace_indent:
    move.w  _trace_depth,d3
    beq.s   .idone
    lea     _trace_spaces,a0   ; "  " (2 spaces)
.iloop:
    bsr     _trace_write
    subq.w  #1,d3
    bne.s   .iloop
.idone:
    rts

;----- _trace_write -----
; Write null-terminated string at a0 to trace file
; Preserves all regs except d0-d1 (already saved by caller)
_trace_write:
    move.l  a0,a3              ; save start
    ; compute length
    move.l  a0,d3
.wlen:
    tst.b   (a0)+
    bne.s   .wlen
    sub.l   d3,a0
    subq.l  #1,a0
    move.l  a0,d3              ; d3 = length
    beq.s   .wdone
    move.l  _DOSBase,a6
    move.l  _trace_fh,d1
    move.l  a3,d2              ; buffer
    jsr     _LVOWrite(a6)
.wdone:
    rts

;----- _trace_write_trunc -----
; Write string at a0, max 64 chars
_trace_write_trunc:
    move.l  a0,a3
    moveq   #0,d3
.tlen:
    tst.b   (a0)+
    beq.s   .tgo
    addq.l  #1,d3
    cmpi.l  #64,d3
    blt.s   .tlen
.tgo:
    tst.l   d3
    beq.s   .tdone
    move.l  _DOSBase,a6
    move.l  _trace_fh,d1
    move.l  a3,d2
    jsr     _LVOWrite(a6)
.tdone:
    rts

;----- _trace_ltoa -----
; Convert signed long in d0 to decimal string at a0
; Returns a0 pointing to start of string (null-terminated)
_trace_ltoa:
    move.l  a0,a3              ; save buffer start
    tst.l   d0
    bpl.s   .lpos
    neg.l   d0
    move.b  #'-',(a0)+
.lpos:
    ; divide repeatedly by 10, push digits
    moveq   #0,d2              ; digit count
    move.l  sp,a1              ; save sp
.ldiv:
    ; d0 / 10 -> quotient in d0, remainder in d1
    move.l  d0,d1
    divu    #10,d1             ; d1.w = quotient, d1 high = remainder
    move.w  d1,d0              ; quotient
    swap    d1                 ; d1.w = remainder
    add.w   #'0',d1
    move.w  d1,-(sp)           ; push digit (as word)
    addq.l  #1,d2
    ext.l   d0
    tst.l   d0
    bne.s   .ldiv
    ; pop digits in correct order
.lpop:
    move.w  (sp)+,d1
    move.b  d1,(a0)+
    subq.l  #1,d2
    bne.s   .lpop
    move.b  #0,(a0)            ; null terminate
    move.l  a3,a0              ; return start
    rts

;----- _trace_hex32 -----
; Convert unsigned long in d0 to 8 hex chars at a0
; a0 is advanced past the hex digits (NOT null-terminated)
_trace_hex32:
    moveq   #7,d2
.hloop:
    rol.l   #4,d0
    move.l  d0,d1
    andi.l  #$0F,d1
    cmpi.b  #10,d1
    blt.s   .hdig
    addq.b  #7,d1             ; 'A'-'0'-10 = 7
.hdig:
    add.b   #'0',d1
    move.b  d1,(a0)+
    dbf     d2,.hloop
    rts

NOTE on _trace_ltoa: The divu instruction works on unsigned 32/16
division. For numbers > 65535, we need a proper 32-bit division.
The existing runtime has _ldivu in lmath.s. We could use that, or
implement a simple decimal conversion using repeated subtraction
of powers of 10.

REVISED _trace_ltoa: Use the existing _sprintf from the C library
with "%ld" format, similar to how _strlong works in string.s:

============================================================
RISKS AND MITIGATIONS
============================================================

1. Stack overflow from trace calls
   Risk: Each trace call saves/restores ~10 registers (40 bytes)
   Mitigation: ACE programs use 40000-65000 stack. Normal SUB nesting
   rarely exceeds 20 levels. 20 * 40 = 800 bytes overhead. Acceptable.

2. Large code size when tracing
   Risk: ~20-30 extra instructions per SUB
   Mitigation: Only emitted with -t flag. Zero overhead without it.

3. FFP float display
   Risk: No easy FFP->decimal conversion available
   Mitigation: Display as hex ($XXXXXXXX). Users can decode manually.
   Future: could add FFP->decimal using mathffp.library SPFix + SPTst.

4. _trace_ltoa overflow for large numbers
   Risk: divu only handles 16-bit division
   Mitigation: Use _sprintf with %lu format (already in runtime).

5. String parameter display truncation
   Risk: Very long strings could overflow buffer
   Mitigation: Truncate to 64 chars in _trace_write_trunc.

6. Trace file I/O performance
   Risk: AmigaDOS Write() for every trace call could be slow
   Mitigation: Acceptable for debugging. Could add buffering later
   if needed, but simplicity wins for v1.

7. _DOSBase availability
   Risk: _trace_open is called after _startup which opens dos.library,
   so _DOSBase is valid. Module mode may not have _DOSBase if the main
   program doesn't use DOS directly.
   Mitigation: The trace functions check _trace_fh != 0 before writing.
   If _trace_open fails (no _DOSBase), all subsequent trace calls are
   no-ops. Main programs always have _DOSBase via _startup.

============================================================
OPEN QUESTIONS
============================================================

1. Should modules (-m -t) also trace? Currently yes, but the trace
   file is opened by the main program. Module trace calls will write
   to the same file. This should work since all code runs in the same
   process.

2. Should DEF FN be traced? Currently no (they're simple expression
   functions). Could add later.

3. RESOLVED: CALLBACK SUBs are NOT traced (called from external C/asm,
   different parameter setup, register save/restore makes it complex).

4. File name configurable? Currently hardcoded to T:ace_trace.log.
   Could make it an environment variable or compiler option later.

5. TRON/TROFF without -t: Currently no-ops (parsed but no code emitted).
   Alternative: TRON could implicitly enable instrumentation. But since
   instrumentation is a compile-time decision affecting all SUB
   definitions, and TRON is a runtime statement, this isn't feasible
   without a two-pass compiler. Decision: require -t for instrumentation.
