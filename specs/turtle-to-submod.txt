Turtle Graphics: Remove Built-in Commands, Replace with Submodule
=================================================================

Status: DRAFT
Branch: (create from master when ready)

Overview
--------
ACE currently has 13 turtle graphics commands hard-coded as reserved words
with compiler handlers and runtime assembly. This spec describes removing
them from the compiler/runtime and providing equivalent functionality as
an external submodule (submods/turtle/).

This frees up 13 reserved words, removes ~170 lines of compiler code,
~390 lines of runtime assembly, and ~4 lines of C runtime init code,
while keeping turtle graphics fully available as an EXTERNAL module.

Plan
----

### Phase 1: Create the Turtle Submodule (submods/turtle/)

Create a BASIC submodule that provides equivalent functionality using
direct graphics library calls and math. The submodule approach means:
- Users include it with: EXTERNAL turtle
- Functions become SUBs: TurtleForward(n), TurtleBack(n), etc.
- Query functions become SUBs returning values: TurtleHeading, TurtleXcor, TurtleYcor

File: submods/turtle/turtle.b

The submodule will:
- Maintain internal state (position, heading, pen state) as module-level variables
- Use LIBRARY "mathffp.library" and "mathtrans.library" for sin/cos
- Use LIBRARY "graphics.library" for Move/Draw
- Provide TurtleInit(initX, initY) to set home position and reset state
  (replaces the automatic init that window.c currently does)

API mapping (old built-in -> new submod):

  BACK n           -> TurtleBack(n)          ' n is SINGLE (float)
  FORWARD n        -> TurtleForward(n)       ' n is SINGLE (float)
  HOME             -> TurtleHome
  PENDOWN          -> TurtlePenDown
  PENUP            -> TurtlePenUp
  SETHEADING n     -> TurtleSetHeading(n)    ' n is SHORT (degrees)
  SETXY x, y       -> TurtleSetXY(x, y)     ' x,y are SHORT
  TURN n           -> TurtleTurn(n)          ' n is SHORT (degrees)
  TURNLEFT n       -> TurtleTurnLeft(n)      ' n is SHORT (degrees)
  TURNRIGHT n      -> TurtleTurnRight(n)     ' n is SHORT (degrees)
  HEADING          -> TurtleHeading          ' returns SHORT
  XCOR             -> TurtleXcor             ' returns SHORT
  YCOR             -> TurtleYcor             ' returns SHORT
  (new)            -> TurtleInit(x, y)       ' set home pos + reset

Header: include/submods/turtle.h

Test: submods/turtle/test_turtle.b
  - Basic movement and drawing test (visual verification on emulator)

Risks and Considerations
------------------------

1. Token enum reordering: Removing entries from the middle of the enum
   shifts all subsequent token values. The rword[] array and enum MUST
   stay in sync (alphabetical order). This is a mechanical but careful
   change - every entry after the removed ones gets a new numeric value,
   but since tokens are compared symbolically (not by number), this is
   safe as long as the array and enum match.

2. BACK/FORWARD dual use: These tokens serve double duty for
   SCREEN BACK/FORWARD. They MUST be kept as reserved words even though
   their turtle statement handlers are removed. The standalone
   BACK n / FORWARD n statements will become syntax errors (unknown
   statement), which is the desired behavior - users should use the
   submodule instead.

3. SETXY dual use: SETXY is also mentioned in docs as usable for
   non-turtle positioning. Check if SETXY has any non-turtle use in
   the codebase. If not, it can be safely removed as a reserved word.
   If it does, it needs to stay (like BACK/FORWARD for SCREEN).
   -> After review: SETXY is only used for turtle graphics in the
   compiler. It can be fully removed.

4. Window init removal: The current runtime auto-initializes turtle
   state on every WINDOW open. After removal, programs that don't use
   the turtle submodule won't carry this overhead. Programs that do
   use turtle must call TurtleInit() explicitly - this is better
   design (explicit > implicit).

5. Backward compatibility: Existing programs using built-in turtle
   commands will break. They must be updated to use the submodule.
   This is acceptable for a language evolution - the submodule provides
   identical functionality with slightly different syntax.

6. Math library dependency: The built-in turtle handlers auto-enter
   XREFs for _MathBase and _MathTransBase. The submodule will use
   LIBRARY statements to open these, which is the standard approach
   for BASIC code.

7. db.lib size: Removing turtle.s and turtle_data.s from db.lib
   reduces the library size slightly. Programs that don't use turtle
   will be marginally smaller.
